# Contributing to AFTERTIDE

Start with a focused issue and a small, reviewable change. Preserve save schema,
stable IDs and deterministic geography/resource placement unless a migration is
included. All player-facing text is English. Explain new balance values.

Build the game and run the domain checks before opening a pull request. For
physics, UI, graphics or navigation changes, report the actual engine version,
reproduction route, renderer and relevant screenshots/logs. Compilation is not
proof of gameplay, appearance or performance. State checks you could not run.

Keep generated caches, model weights, saves, secrets and private prompts out of
commits. Use original or cleared assets and add their exact source/license to
NOTICE and docs/SOURCES. Do not extract content from commercial games. Submit
only work you have the right to contribute under the project's license.

AI-assisted contributions are welcome with normal human review, tests and
provenance. The game must not acquire a required AI-service dependency. Do not
submit unreviewed generated output or claim automated tests are manual playtests.

Prefer Conventional Commit messages. A pull request should explain the problem,
behavior change, compatibility, validation and remaining limitations. Avoid
unrelated formatting or mass asset changes. Never force-push another contributor's work.
